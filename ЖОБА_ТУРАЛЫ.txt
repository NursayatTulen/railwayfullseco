EcoHub KZ — Жоба туралы қысқаша мәлімет
==========================================

Бұл — Қазақстанның экологиялық жобалары мен іс-шараларын
басқаруға арналған веб-платформа. Laravel + Spatie Permission
негізінде жасалған, рольге негізделген қол жеткізу жүйесімен (RBAC).

ЖАҢА ПАЙДАЛАНУШЫ ТІРКЕЛСЕ
---------------------------
Тіркелу кезінде автоматты түрде "user" ролі беріледі.
Ролді жоғарылату тек Admin немесе Super-Admin арқылы жүзеге асады.


ЖОБА ҚҰРЫЛЫМЫ (қысқаша)
--------------------------
  app/
    Models/          — EcoProject, EcoEvent, User
    Http/Controllers — EcoProjectController, EcoEventController,
                       DashboardController, Auth/AuthController

  resources/views/
    layouts/app      — Негізгі шаблон (navbar, стильдер)
    eco-projects/    — Жобалар (index, create, edit)
    eco-events/      — Іс-шаралар (index, create, edit)
    admin/           — Admin панелі, Аналитика
    auth/            — Кіру, Тіркелу беттері
    dashboard        — Басты бет (рольге сай мазмұн)

  routes/web.php     — Барлық маршруттар (permission middleware)
  database/
    migrations/      — Кесте схемалары
    seeders/         — Рольдер, рұқсаттар, тест аккаунттары


ІСКЕ ҚОСУ
----------
  php artisan serve          # Серверді қосу → http://127.0.0.1:8000
  php artisan db:seed        # Тест деректерін жүктеу (рольдер + аккаунттар)
  php artisan migrate        # Миграция іске қосу

ЖОБАНЫ ҚЫСҚАША ТАНЫСТЫРУ (1-2 минут)
--------------------------------------
"Бұл жоба — EcoHub KZ деп аталады. Қазақстанның экологиялық
жобалары мен іс-шараларын басқаруға арналған веб-платформа.
Жүйе Laravel фреймворкі негізінде жасалған. Ең басты ерекшелігі —
рольге негізделген қол жеткізу жүйесі, яғни RBAC (Role-Based
Access Control). Spatie Laravel Permission кітапханасы арқылы
іске асырылған. Жүйеде 4 роль бар: super-admin, admin,
moderator және user. Әр роль өзіне тиесілі рұқсаттар шегінде
ғана жұмыс жасай алады."


КҮТІЛЕТІН СҰРАҚТАР ЖӘНЕ ЖАУАПТАР
----------------------------------

С: RBAC дегеніміз не?
Ж: Role-Based Access Control — рольге негізделген қол жеткізуді
   басқару жүйесі. Пайдаланушыға тікелей рұқсат бермейміз,
   оның орнына роль береміз, ал роль арқылы рұқсаттар
   автоматты түрде қолданылады. Бұл қауіпсіздікті арттырады
   және басқаруды жеңілдетеді.

С: Неге Laravel таңдадыңыз?
Ж: Laravel — PHP-дың ең танымал фреймворкі. Маршруттау,
   аутентификация, миграция, Eloquent ORM сияқты дайын
   мүмкіндіктері бар. Уақытты үнемдейді, кодты таза ұстайды.

С: Spatie Permission дегеніміз не?
Ж: Laravel үшін жасалған рольдер мен рұқсаттарды басқаруға
   арналған кітапхана. Рольдерді, рұқсаттарды деректер базасында
   сақтайды. Blade-да @can, @role директиваларын қамтамасыз
   етеді. Бірден орнатып, пайдалана беруге болады.

С: Деректер базасы ретінде не пайдаландыңыз?
Ж: SQLite пайдаландым. Тестілеу мен оқу мақсатында өте ыңғайлы,
   бөлек сервер орнатудың қажеті жоқ, файл ретінде сақталады.
   Өндіруге MySQL немесе PostgreSQL-ге оңай ауыстыруға болады.

С: Аутентификация қалай жұмыс жасайды?
Ж: Пайдаланушы тіркелгенде құпия сөз bcrypt арқылы хэшталады,
   ешқашан тікелей сақталмайды. Кіргенде Laravel-дің Auth::attempt()
   әдісі хэшті салыстырады. Сессия арқылы кіру күйі сақталады.

С: Middleware дегеніміз не, қалай қолдандыңыз?
Ж: Middleware — HTTP сұранысы контроллерге жеткенге дейін
   өтетін сүзгі. Мен 'permission:...' және 'role:...' middleware
   қолдандым. Мысалы, эко-жоба жасау беті тек 'create eco-projects'
   рұқсаты бар пайдаланушыларға ашылады. Рұқсаты жоқ болса,
   жүйе автоматты 403 қате қайтарады.

С: Пайдаланушы тіркелгенде қандай роль береді?
Ж: AuthController-да тіркелу кезінде автоматты түрде 'user' ролі
   тағайындалады. Ролді жоғарылату тек super-admin арқылы
   admin панелінен жүзеге асады.

С: Blade шаблондары дегеніміз не?
Ж: Laravel-дің шаблон қозғалтқышы. HTML ішінде {{ }} арқылы
   PHP мәндерін шығарамыз, @if, @foreach, @can сияқты
   директивалар кодты оқуды жеңілдетеді. @can('create eco-projects')
   директивасы тек рұқсаты бар пайдаланушыға батырманы көрсетеді.

С: Mass Assignment дегеніміз не?
Ж: Пайдаланушы формадан жіберген барлық деректерді тікелей
   деректер базасына жазу қауіпті. Сол себепті модельде $fillable
   массивімен рұқсат етілген өрістерді анықтаймыз, ал
   контроллерде $request->only(['title', 'description']) арқылы
   тек қажетті өрістерді аламыз.

С: Жобаны жегілтіру үшін не қосар едіңіз?
Ж: API (REST), пайдаланушы профилі өңдеу, email арқылы
   хабарлама жіберу, файл жүктеу мүмкіндігі, жобаларды іздеу
   мен сүзгілеу функциялары қосылуы мүмкін. Сонымен қатар
   MySQL деректер базасына ауыстырып, production серверіне
   орналастыруға болады.
